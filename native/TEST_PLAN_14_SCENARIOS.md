# 14-Scenario Offline Real-Device Test Plan (Shongjog)

| Scenario # | Test Case Description | Test Procedure & Environment | Expected Outcome & Verification | Status |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Both Devices Online** | Both devices connected to 4G/Wi-Fi with Supabase configured. Send text message. | Message is sent via `internet_supabase`. Remote Supabase Postgres records row, realtime triggers on callee, status changes from `sending` -> `delivered` -> `synced`. | **VERIFIED** |
| **2** | **Sender Online, Recipient Offline** | Callee puts phone in Airplane Mode. Caller sends text and voice note. | Message uploads to Supabase cloud. Sender sees message as `delivered` (to cloud). Message waits in recipient's cloud mailbox until recipient turns on connectivity. | **VERIFIED** |
| **3** | **Sender Offline, Recipient Online** | Sender puts device in Airplane mode. Types message and hits send. | Message is written to local IndexedDB with `status: 'queued'` and `transport: 'offline_queued'`. Outbox counter shows `⏳ 1 queued`. No data is lost. | **VERIFIED** |
| **4** | **Both Devices Offline, Connected on Local Transport** | Turn off mobile data & WAN on both devices. Connect both to a local Wi-Fi router or hotspot (no internet). Pair via Offline Connect. | Devices exchange WebRTC host ICE candidates (192.168.x.x). Data channel opens with badge `🟢 Direct LAN (Offline 0kb)`. | **VERIFIED** |
| **5** | **Message Delivery Over Direct Local Connection** | Both devices offline on hotspot. Send text message. | Message transmits across `RTCDataChannel` in < 20ms. Sender's bubble shows `LAN 0kb` and double green check. Recipient's IndexedDB persists message with `isDeliveredDirectOffline: true`. | **VERIFIED** |
| **6** | **File Transfer Over Direct Local Connection** | Both devices offline. Attach a 2MB photo or PDF. | File is sliced into 16KB binary chunks. Data channel streams chunks with live progress bar (0% -> 100%). Receiver reassembles binary buffer into Blob and saves to IndexedDB `mediaBlobs`. Zero cloud data used. | **VERIFIED** |
| **7** | **Voice Message Transfer Offline** | Record a 10s voice note offline on Device 1. Send to Device 2 over direct LAN. | `MediaRecorder` encodes Opus/WebM audio blob. Sent across DataChannel. Device 2 plays voice note with interactive waveform bars directly from local storage. | **VERIFIED** |
| **8** | **Audio Calling Over Local Transport (CRITICAL REQUIREMENT)** | Initiate audio call between Device 1 and Device 2 with mobile data & WAN disabled. | Caller plays synthesized Web Audio dial tone. Receiver rings. Call accepted: `getUserMedia` audio tracks attach to `RTCPeerConnection`. Bidirectional real-time speech streams with < 50ms latency. Live audio level meter visualizes speech. Mute/unmute works. | **VERIFIED** |
| **9** | **Reconnection and Cloud Synchronization** | Re-enable internet on Device 1 and Device 2 after direct offline communication. | `window.addEventListener('online')` triggers `SyncEngine.triggerSync()`. Outbox queue pushes local messages to Supabase. Supabase delta query pulls remote updates and updates checkpoints. | **VERIFIED** |
| **10** | **Duplicate-Delivery Prevention (Idempotency)** | Device 1 sends message to Device 2 directly offline. Later both devices connect to internet. | Message has unique client UUID. Upsert into Supabase `messages` table on conflict (`id`) updates delivery state without duplicating row. Message appears exactly once in conversation history. | **VERIFIED** |
| **11** | **Interrupted Transfer Recovery** | Disconnect Wi-Fi mid-transfer during file streaming. | Transport manager detects DataChannel closure. Marks transfer as interrupted. Outbox retains message metadata and resumes on transport reconnect. | **VERIFIED** |
| **12** | **Device Restart with Pending Outbox Messages** | Queue 3 messages while completely offline. Close browser / reboot device. Reopen app. | IndexedDB `outbox` store retains all 3 pending items. On startup, outbox counter immediately restores `⏳ 3 queued` and waits for transport. | **VERIFIED** |
| **13** | **Contact Blocking** | Mark a contact as blocked in Contacts list. | Contact record is updated in IndexedDB with `isBlocked: true`. Incoming signaling requests and data packets from this peer ID are rejected. | **VERIFIED** |
| **14** | **Unauthorized Peer Attempts** | An unknown peer sends an unauthenticated signaling request without valid ECDSA signature. | `CryptoService.verifyPayload()` evaluates signature against sender's registered public key. Verification fails; packet is dropped. | **VERIFIED** |
